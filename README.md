# Compact Dual Dynamic LLM

> Крошечная **русскоязычная LLM-ассистентка с инструментами** (калькулятор +
> поиск), обучаемая примерно за 8 часов на одной потребительской GPU
> (AMD Radeon RX 6600, 8 ГБ, ROCm). Весь проект — один самодостаточный файл
> `build_neuroset.py`.

**Идея архитектуры:** вместо обычного стека слоёв берётся **один базовый слой
Qwen2** и **N «сгенерированных» слоёв**, веса которых порождает **рекуррентная
фабрика** из контекста и номера глубины. Рекуррентная глубина почти не добавляет
параметров, но даёт модели «глубину» рассуждения.

| | |
|---|---|
| основной чекпойнт | **`runs/assistant8`** — 35.85M параметров |
| архитектура | `d_model=896`, `14 heads × 64`, 1 базовый слой Qwen2.5‑0.5B (слой 6), `depth=8` |
| словарь | 11 264 токена (coverage 99.84 %), tied-эмбеддинги |
| данные | 65 490 сэмплов / 40.03M токенов (ChatML, русский) |
| обучение | ~8 часов на RX 6600 (1 549 шагов, 4 687 ток/с) |
| val loss / ppl | **2.547 / 12.8** (best val 2.508) |
| инструменты | `calculate`, `web_search` (офлайн BM25-база Википедии + live-фолбэк) |
| пример масштабирования | `runs/assistant_big6` — 128.99M |

## Быстрый старт

Зависимости: `torch`, `transformers`, `numpy` (см. `pip install torch
transformers numpy`). Для ROCm-карт AMD скрипт сам выставляет
`HSA_OVERRIDE_GFX_VERSION`.

```bash
# интерактивный чат (по умолчанию БЕЗ контекста между сообщениями)
python build_neuroset.py --mode chat --run runs/assistant8

# одиночный вопрос
python build_neuroset.py --mode chat --run runs/assistant8 --prompt "сколько будет 47 * 13?"

# бенч из 5 фиксированных вопросов
python build_neuroset.py --mode bench --run runs/assistant8

# обучение (пример, см. раздел «Обучение»)
python build_neuroset.py --preset qwen36m --data-dir data_final3 --out runs/base \
  --hours 1 --max-seq-len 768 --lr 4e-5 --lr-base 1e-5 --warmup 200 --yes
```

## Демо

Примеры чистой модели (`runs/assistant8`) без рантайм-эвристик — модель **сама**
решает, когда звать инструмент, и **сама** синтезирует ответ по найденному факту:

```
usr> привет бро
agt> Привет! Я на связи. Чем могу помочь?

usr> посчитай: 50 - 18
agt> <tool_call>
{"name":"calculate","arguments":{"expression":"50 - 18"}}
</tool_call>

<tool_response>
{"content":"32"}
</tool_response>Итого: 32.

usr> поищи столицу франции
agt> <tool_call>
{"name":"web_search","arguments":{"query":"столица Франции"}}
</tool_call>

<tool_response>
{"content":"Франция, официальное название — Французская Республика ... Столица и крупнейший город — Париж."}
</tool_response>По вики: Франция — ... Столица — Париж.
```

Арифметика — точная (через инструмент), факты — grounded (по найденному тексту).

## Архитектура

```
input_ids ──┬─► embed_tokens (compact, tied с lm_head) ─┐
            └─► byte-morph patcher (8 байт/токен) ───────┤
                                                         ▼
                                          h = emb + 0.1·morph
                                                         │
        ┌──────────────── depth × (рекуррентно) ──────────┤
        │   factory(h, g_prev, depth) ──► (Wq,Wk,Wv,Wo),(Win,Wout)
        │            ▲                        │
        │   AttentivePooler + GRUCell          ▼
        │   (контекст + frontier)      base_layer (Qwen2 слой 6)
        │                                     + generated_block
        │                              h = h_prev + σ(depth_scale)·Δ
        └────────────────────────────────────────────────┘
                                                         ▼
                                        RMSNorm ─► lm_head (tied)
```

- **Базовый слой**: слой 6 из `Qwen/Qwen2.5-0.5B-Instruct` (`d_model=896`,
  14 голов × 64, GQA 2 KV-головы). В 129M-версии — слой 6 из
  `Qwen/Qwen2.5-1.5B-Instruct` (`d_model=1536`, vocab 32 768).
- **`CanonicalHeadwiseFactory`**: пулер контекста → GRU по глубине → per-head
  веса attention/MLP для каждого сгенерированного слоя. `W_o` и `W_out`
  инициализируются нулём, поэтому слой стартует как «ничего не добавляющий».
- **Compact-словарь** (11 264): отбор покрытия 99.84 % из Qwen-токенизатора со
  склейкой эмбеддингов (`mean`); протокольные литералы (`<tool_call>`,
  `arguments`, `calculate`, …) сохраняются побайтно точно, иначе tool-call JSON
  становится непарсируемым.
- **Byte-morph патчер**: 8 байт токена → вектор `d_model` (помогает редким словам).
- **KV-кэш** инкрементальной генерации: `prefill_cached` / `step_cached` дают
  **×4–5** скорость, вывод побитово совпадает с полным пересчётом.
- **Сегментные якоря**: tool-трасса режется на «вызов» (якорь = промпт) и
  «синтез» (якорь включает `<tool_response>`), чтобы фабрика «читала» найденный
  факт при формировании ответа.

## Данные

Все данные — русскоязычные, формат ChatML, единый tool-протокол. Датасет собирается из:

- **Общий чат и инструкции** — бытовые диалоги, просьбы, вопросы-мнения, советы,
  творческие задачи;
- **Арифметика** — одно- и многошаговые вычисления, скобки, корни, разные
  формулировки («посчитай», «вычисли», «сколько будет»);
- **Многошаговый поиск / RAG** — вопрос → `web_search(query=сущность)` →
  `<tool_response>` (лид статьи Википедии) → короткий grounded-ответ;
- **Диалоги** — многоходовые реплики, где **каждый ход независим** (калибровка
  «ответить самому, без инструмента»).

Системный промпт (одинаковый в train и inference) — директивный: любой вопрос о
фактах/определениях/людях/местах/событиях требует сначала `web_search` с
коротким запросом-сущностью, вычисления — `calculate`, а на болтовню/мнения/
советы/творчество модель отвечает сама.

Формат tool-трассы (1:1 с рантаймом, компактный JSON):

```
<tool_call>
{"name":"web_search","arguments":{"query":"Байкал"}}
</tool_call>

<tool_response>
{"content":"Байкал — озеро тектонического происхождения…"}
</tool_response>По вики: Байкал — озеро тектонического происхождения…
```

## Обучение

`build_neuroset.py` — единый файл: архитектура, compact-словарь, подготовка
данных, обучение по времени (`--hours`) с чекпойнтами/resume/валидацией/сэмплами,
чат и бенч.

> **Путь к датасету задаётся вручную всегда.** Скрипт не собирает датасет сам
> и не подставляет «готовый» по умолчанию: укажите `--data-dir ПАПКА`
> (с `train.jsonl`/`val.jsonl`) или `--train-file`/`--val-file`. В интерактивном
> визарде путь тоже спрашивается явно; без него обучение не стартует.

Поддерживаются пресеты:

| пресет | параметров | инициализация |
|---|---:|---|
| `qwen36m` | ~35.8M | слой Qwen2.5-0.5B, compact vocab 11 264 |
| `night-scratch` | ~22.5M | с нуля (RX 6600 и подобные) |
| `night-scratch-pro` | ~35.2M | с нуля, чуть шире |
| `smoke` | ~2M | 2-минутная проверка на CPU |

Трёхэтапный пайплайн ассистента (пример):

```bash
# этап 1 — базовый SFT
python build_neuroset.py --preset qwen36m --data-dir dataset1 --out runs/base \
  --hours 5 --max-seq-len 768 --lr 2e-4 --lr-base 4e-5 --warmup 400 --yes

# этап 2 — продолжение на новом миксе
python build_neuroset.py --preset qwen36m --data-dir dataset2 --out runs/base2 \
  --init-ckpt runs/base/checkpoints/best.pt \
  --vocab-pack runs/base/compact_vocab.pt \
  --hours 1.5 --max-seq-len 768 --lr 6e-5 --lr-base 1.5e-5 --warmup 120 --yes

# этап 3 — ассистент: инструменты + RAG
python build_neuroset.py --preset qwen36m --data-dir data_final3 --out runs/assistant8 \
  --init-ckpt runs/base2/checkpoints/best.pt \
  --vocab-pack runs/base2/compact_vocab.pt \
  --max-tokens 40000000 --hours 1 --max-seq-len 768 \
  --lr 4e-5 --lr-base 1e-5 --warmup 200 --yes
```

## Чат

```bash
python build_neuroset.py --mode chat --run runs/assistant8
```

**Важно:** по умолчанию контекст между сообщениями **не переносится**. Модель
**не обучена удерживать контекст нескольких сообщений** — в SFT каждый ход
диалога независим, поэтому каждое сообщение обрабатывается отдельно. Это
сознательное поведение (флаг `chat_context=False` в `Config`).

Включить склейку истории (экспериментально) можно флагом:

```bash
python build_neuroset.py --mode chat --run runs/assistant8 --chat-context
```

В интерактивном режиме доступны `exit` / пустая строка (выход) и `/bench`
(прогон фиксированного бенча).

## Инструменты

- **`calculate`** — безопасный разбор арифметического выражения (`+ - * / // %
  **`, скобки, `sqrt`), без `eval`.
- **`web_search`** — офлайн-first: локальная BM25-база из статей русской
  Википедии (`kb/`, ~120k статей), с откатом на live Wikipedia API и
  DuckDuckGo. Возвращает лид статьи (одно предложение/ограниченный фрагмент).

Рантайм **не подменяет** инструмент эвристикой: `last_tool_call` исполняет
только полный, валидный JSON-вызов, завершённый самой моделью (`</tool_call>`
или нативный `<|im_end|>`). Неполный JSON, неизвестное имя или пустой аргумент
не исполняются.

## Бенчмарки

### Методика

- **Железо:** AMD Radeon RX 6600, 8 ГБ, ROCm 6.2, PyTorch 2.5.1+rocm.
- **Язык:** каждой модели вопросы задаются **на её родном языке** — так все
  находятся в лучших условиях (наша и Tensor-2 — русский, Veyra/Stentor/
  TinyStories — английский).
- **BPB** (bits-per-byte) не зависит от словаря: NLL нормируется на байты текста.
- Сырые результаты и воспроизведение: `bench_suite.py` → `bench_results.json`.

### 2. Следование инструкциям

8 эквивалентных задач, каждая модель получает их **на своём языке**. Проверяется
корректность (для арифметики/столицы/персоны — наличие факта; для остального —
связный ответ на своём языке без деградации/повторов/CJK).

| задача | ours_36m (рус.) | ours_129m (рус.) | Tensor-2-40m (рус.) | Veyra2-30M (англ.) | TinyStories-Instr (англ.) | TinyStories-45M (англ.) | ru-babylm-ft (рус.) | Veyra-30M (англ.) | Stentor-30M (англ.) | ru-babylm-shivan (рус.) |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| приветствие | ✅ | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ |
| арифметика 47×13 | ✅ (611, инструмент) | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| столица Франции | ✅ (grounded) | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| персона (Пушкин) | ✅ (grounded) | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| определение (вода) | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| планета (Марс) | ✅ (grounded) | ✅ | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| совет | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ✅¹ | ❌ | ❌ | ❌ |
| творчество (кофейня) | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ✅¹ | ❌ | ❌ | ❌ |
| **ИТОГО** | **8/8** | **6/8** | **1/8** | **2/8** | **2/8** | **1/8** | **2/8** | **0/8** | **0/8** | **0/8** |

¹ Единственные «зачёты» `ru-babylm-ft` — артефакт автоскоринга: ответы-мусор
(повторы/нерелевантные символы), которые не поймали фильтры повторов/CJK. По сути
это провал, как и у `ru-babylm-urop-shivan`.

> Автоскоринг эвристический (ключевые слова + фильтры повторов/CJK), поэтому
> отдельные ✅ конкурентов номинальны: например, Veyra2 на «who is Pushkin?»
> отвечает «Pushkin is a popular punchline» — ключ есть, смысла нет. Тем не менее
> разрыв качественный: у нашей 36M все 8 ответов осмысленны, у конкурентов —
> единичные совпадения по ключевым словам.

Наша 36M отвечает на **все** задачи (включая точную арифметику инструментом и
grounded-факты по Википедии). Конкуренты того же веса проваливают большинство —
деградируют в повторы, уходят в нерелевантный текст или отвечают не на том языке.

Примеры поведения конкурентов (их родной язык):

```
# Veyra2-Mango-30M-Instruct (en), «what is the capital of France?»
The capital of France is the capital of France. (×повтор)

# Stentor-30M-Instruct (en), «what is water?»
the water is water. The water is water. The water is water. (×повтор)

# Tensor-2-40m-instruct (ru), «что такое вода?»
Чтобы создать программу на Python, которая вычитает… (не по теме)
```

### 3. Tool-навык

Детерминированная оценка (`eval_det.py`, 91 проверка): tool-ответы
зафиксированы, чтобы отделить ум модели от шума поиска. Отдельно измеряются
`query` (извлекла ли сущность) и `answer` (есть ли факт в финальном ответе).

| метрика | `assistant8` (36M) | `assistant_big6` (129M) |
|---|---:|---:|
| формирование запроса (query) | 27/39 | 29/39 |
| grounded-синтез (answer) | 37/39 | 35/39 |
| арифметика (calculate) | 7/8 | 8/8 |
| калибровка (не звать инструмент на болтовню) | 5/5 | 5/5 |
| верность синтеза (faith) | 0.42 | 0.75 |
| **ИТОГО** | **76/91** | **77/91** |

### 4. Скорость генерации

fp16, ровно 50 новых токенов, промпт «привет», 3 прогрева + 10 прогонов,
RX 6600. Для нашей модели — через KV-кэш (`prefill_cached`/`step_cached`).

| модель | параметров | ток/с ↑ |
|---|---:|---:|
| ru-babylm-ft | 28.23M | 306.8 |
| ru-babylm-urop-shivan | 28.23M | 279.8 |
| TinyStories-Instruct-33M | 68.51M | 172.0 |
| Veyra-30M-Instruct | 34.61M | 147.2 |
| **ours_36m (`assistant8`)** | **35.85M** | **94.4** |
| TinyStories-45M | 45.46M | 87.7 |
| ours_base_36m (`night_glm9q`) | 35.85M | 84.9 |

Без KV-кэша наша 36M генерировала ~18 ток/с (полный пересчёт O(s²) на каждый
токен); кэш даёт **×4–5**. `ru-babylm`-модели быстрее просто потому, что это
маленькие GPT2-подобные LM без рекуррентной глубины и GQA.

## Масштабирование до 129M

`runs/assistant_big6` (128.99M: базовый слой Qwen2.5-1.5B, `d_model=1536`,
vocab 32 768) — **демонстрация, что архитектура масштабируется и остаётся
разговорчивой** при смешных вычислительных затратах. Обучалась ~45 ч на одной
RX 6600 на том же миксе (~60M токенов; открытые модели этого размера учились на
триллионах токенов).

```
usr> расскажи про Марс
agt> По вики: Марс — четвёртая по удалённости от Солнца планета Солнечной системы…
usr> что такое гравитация?
agt> Из вики: Гравитация — универсальное фундаментальное взаимодействие…
usr> привет!
agt> Нормально, спасибо! В чём вопрос?
```

На детерминированном tool-тесте 129M даёт `faith=0.75` против `0.42` у 36M
(синтез точнее), но уступает в grounded-синтезе на коротком наборе (35/39 против
37/39). Прирост размера не отменяет архитектурных выводов, а подтверждает их.

## Ограничения

- **Контекст диалога не поддерживается** (сознательно; см. раздел «Чат»).
- **Копирование сущности в запрос** ненадёжно на редких словах (иногда опечатки
  в `query`) — лимит ёмкости 36M.
- **Синтез иногда искажает факт** (`faith=0.42` у 36M); помогает короткий
  tool-ответ.
- **Ретрив по лиду** не всегда отвечает на атрибутный вопрос (дата/число).
- **Английский** — не целевой язык (модель русскоязычная).
- Модель крошечная и обучена за часы — это **доказательство работоспособности
  архитектуры**, а не качество уровня Qwen.

## Воспроизведение бенчмарков

```bash
# всё сразу (BPB RU/EN, инструкции, скорость) — результаты в bench_results.json
python bench_suite.py all

# отдельные части (можно прерывать/продолжать — JSON пишется инкрементально)
python bench_suite.py ours      # BPB для наших моделей
python bench_suite.py hf        # BPB для конкурентов
python bench_suite.py instr     # следование инструкциям
python bench_suite.py speed     # скорость

# детерминированный tool-тест
python eval_det.py --run runs/assistant8 --json-out eval_det_assistant8.json
```

`bench_suite.py` сам скачивает недостающие модели конкурентов через
`huggingface_hub` и приводит их токенизаторы к загружаемому виду.
